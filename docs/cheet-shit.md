# Чіт-шит: ручне тестування на одному ПК

Два інстанси застосунку в одному Windows-сеансі, без другого фізичного ПК.

## 1. Запуск двох інстансів

```
python src/secure_file_drop_entry.py --pswd shared-pass
python src/secure_file_drop_entry.py --pswd shared-pass --port 52074
```

Або VS Code: launch-конфіги "Python: Secure File Drop (GUI)" і "...- B (port 52074)" — обидва одночасно.

- Парольна фраза — **однакова** в обох.
- Замість `--pswd`: кнопка "Згенерувати" в одному вікні + скопіювати фразу в друге (реалістичніше).
- `--snd-dir <шлях>` — одразу обрати каталог для передачі.
- `--port <номер>` — заповнити поле "Порт" (див. п.2).

## 2. Порт — різний, виставляти ДО хендшейку

Однаковий порт на одній машині → "порт зайнятий" у того, хто слухає другим.

- Найпростіше — `--port` при запуску.
- Зміна порту/фрази/ітерацій у GUI ПІСЛЯ хендшейку → застосунок сам скидає хендшейк/канал, статус "Параметри змінено..." — нормально, згенеруйте/обробіть заново.

## 3. Профіль — окремі каталоги вхідних файлів

За замовчуванням обидва інстанси пишуть у той самий `~/.secure_p2p_filedrop/...`. Щоб не змішувати:

- Вікно B → "Профіль" → "Вхідні файли" → "Обрати..." → окремий каталог → "Зберегти профіль".

## 4. Хендшейк (Фаза 1)

1. Вікно A: "Хендшейк" → "Згенерувати" (tooltip на кнопці пояснює дію) — копіюється в буфер.
2. Вікно B: "Вставити хендшейк" (або Ctrl+V) — обробляється одразу, підпис: "Хендшейк співрозмовника.".
3. Один сеанс — одна роль: повторне "Згенерувати"/"Вставити" при вже активному сеансі питає підтвердження ("Почати новий сеанс?") і скидає попередній хендшейк/канал.
4. Порожня парольна фраза при "Згенерувати"/"Вставити" — з'явиться віконце для її введення (замість попередження).
5. Звірити "Код підтвердження" в обох вікнах — **збігається** (8 hex-символів). Не збігається → віконце в обох: ввести правильну фразу й OK в обох (хендшейк повторно не пересилати).
6. Дочекатись "Канал передачі" → "Підтверджено — канал готовий" (кілька секунд).

"Перевірити канал" (кнопка під статусом) — ping/pong без файлів; корисно ізолювати "канал не встановився" від "передача не спрацювала".

## 5. Передача файлу (Фаза 3)

1. Вікно A (відправник): "Обрати файл..." або "Обрати каталог..." (або `--snd-dir`).
2. Для каталогу: зняти зайві позначки, обрати архів/як є, стиснення, шифрування.
3. "Ініціалізувати передачу" — готує `transfer_payload` (ZIP реально створюється тут, якщо обрано архів); нічого ще не йде в мережу, доступно будь-коли.
4. "Надіслати" — передає підготовлений payload. Активна лише при підтвердженому каналі й виконаному кроці 3.
5. Прогрес-бар під кнопками.
6. Вікно B: перевірити "Вхідні файли" (Профіль).
7. Зворотний напрямок — повторити кроки 1-5 у вікні B (той самий канал, новий хендшейк не потрібен).

## Типові проблеми

- **"Не вдалось з'єднатись" одразу (не за 300с)** — порт зайнятий (п.2).
- **Канал не підтверджується** — статус показує адресу й `(Nс)`; попередження в лозі про NAT hairpin, якщо адреса публічна (обидва інстанси за одним роутером). Якщо застрягло — вимкнути інтернет на хвилину або дочекатись відкату на LAN-only.
- **Коди підтвердження не збігаються** — різна фраза (одруківка) або зіпсований хендшейк.
- **"Надіслати" неактивна** — канал не підтверджено, не натиснуто "Ініціалізувати передачу", або AES-архів зашифровано ключем іншого сеансу (повторити ініціалізацію).

## Автоматичні тести

```
bin/run-tests          # Linux/macOS, усі групи
bin\run-tests.bat       # Windows, усі групи
python tests/_groups.py handshake gui   # напр. після зміни connection.py
python tests/_groups.py fast            # усе, крім transport і gui
python tests/_groups.py data -k prepare # група + unittest-фільтр
```

Групи — [architecture.md](architecture.md). `test_transport.py` іноді флейкає (`KeyError`/`WinError 10053`) — відомий артефакт сетапу, не production-баг; деталі: [testing.md](testing.md).
